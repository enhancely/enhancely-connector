## Architecture

- pnpm monorepo. `packages/injector-core` is the **single source of truth** for all connector logic: URL handling, API client, cache + ETag revalidation, HTML injection, fail-open orchestration.
- Adapters (`adapter-cloudflare`, `adapter-lambda-edge`, `adapter-sidecar`) are **thin**: they translate the platform's request/response shapes to core calls and wire up platform storage. No business logic in adapters.
- TypeScript for core and all edge adapters. CloudFront Lambda@Edge supports **only Node.js and Python** runtimes, so Go is impossible there — TS is the one language that covers every current target. The Go sidecar (`adapter-sidecar-go`, reserved) is a deliberate **later second distribution**, not a rewrite of the core.

## Non-negotiable rules

1. **API key never client-side.** `sk-…` / `sk-org-…` keys stay on the edge/server. Nothing that could leak the key may reach the browser.
2. **Send a URL to Enhancely, never a locally computed hash.** Specifically the query-stripped `normalizeLite(url)` (= the cache key): the server strips the query anyway so the resolved record is identical, but query strings (tokens/PII) never leave the edge. The server still hashes authoritatively. At the network boundary, only absolute HTTP(S) URLs without URL credentials and with a normalization fixed point are accepted; malformed, relative, non-HTTP(S), credential-bearing, and normalization-unstable values fail locally before cache or network access, so an unstripped token or mismatched record key can never fall through.
3. **Fail-open everywhere.** Any error, timeout, oversized JSON-LD body, missing `</head>`, non-HTML, non-2xx origin response, or over-quota Lambda@Edge body/header set → serve the original HTML untouched. Every Enhancely call uses `AbortSignal.timeout` (core/default adapters: 800 ms). JSON-LD bodies are streamed with a 256 KiB hard ceiling.
4. **Own cache + ETag revalidation is mandatory.** The API responds `Cache-Control: no-store`; the connector brings its own cache and revalidates with `If-None-Match` → 304. Concurrent cold/stale lookups for the same normalized URL, cache object, lookup mode, and execution environment are single-flighted; GET and register-or-revalidate stay separate. Local cache writes are serialized: a newly successful `200`/`304`/`412` beats retry-only state, a successful `404` may retire a stale positive while inheriting the longest concurrent retry deadline, and racing transient results retain stale positive data plus that longest deadline. A genuinely newer positive result is never overwritten by an older negative/error. A distributed backend must supply its own atomic/CAS semantics for the same guarantee across isolates; Workers KV is eventually consistent and has no CAS, so that cross-isolate race belongs to the later cache-optimization phase. Workers KV and its fallback memory cache are scoped by Enhancely base/API-key identity; the persisted key uses only a non-secret SHA-256 scope, never the Bearer key. The default `MemoryCache` is bounded by both 5000 entries and a conservative 16 MiB retained-string estimate. High-level `autoRegister` uses the register-or-revalidate POST directly, avoiding GET→404→POST. Only HTTP `429` opens the bounded execution-environment-local circuit for the same `enhancelyBase`/API-key/fetch scope, shared by GET and register-or-revalidate: other URLs serve stale positives or return a negative/missing `revalidateInMs` without another Enhancely call for at most 60 seconds. A register POST may retain its own URL-local `429` backoff or a `403` `Retry-After` for up to 24 hours, but a registration-limit `403` must never suppress other URLs. Plain upstream errors remain URL-local. Custom `fetchImpl` identities isolate tests/adapters, expired scopes are pruned, and each fetch scope retains at most 128 live API-key circuits.
5. **Two Lambda@Edge triggers, one supported pairing.** Deploy the handler-only `src/origin-request-entry.ts` bundle (implemented in `src/origin-request.ts`) plus the cache-cap-only `src/companion.ts` bundle on the SAME cache behavior. Lambda-only `includeHosts` (TF: `include_hosts`) is an exact public-host selector checked by both entrypoints before SSM, connector-origin, Enhancely, registration, or companion cache-cap work; absent/empty means all hosts, while malformed non-empty hand config matches nothing. When several aliases share a behavior and host policy differs, viewer `Host` MUST be in the CloudFront cache policy (an origin request policy alone does not partition cache hits); the static page-host header cannot distinguish aliases. Terraform therefore requires `host_in_cache_key_asserted = true` for every non-empty `include_hosts` list after the operator verifies that external policy. Query-dependent origins MUST expose all query strings through the cache or origin request policy so the direct fetch can reproduce CloudFront's request. The origin-request handler fetches the ORIGIN FIRST and asks Enhancely only after an exact 200 `text/html` response has also passed charset, indexing, transform/disposition, structural `</head>`, header-quota, and minimum body-budget preflights. A no-head page is generated unchanged with zero Enhancely calls. Injectable pages cost one origin hit and may carry `Set-Cookie` or `private|no-store`, because the response returned is the same one fetched. Small reproducible veto responses (including status-200 non-HTML/noindex/unsafe-charset/`no-transform`/non-inline-disposition bodies) and non-2xx answers are returned from that first fetch; a post-lookup snippet-quota veto also returns the already-fetched original HTML whenever it fits. Only responses that cannot safely be generated hand back to CloudFront, and that verdict is memoized per execution environment (`nonPageMemoTtlMs`, default 30 min). Origin-fetch failures use separate bounded 10-second circuits: only proven pre-transport DNS/TCP/TLS failures suppress the endpoint + virtual host; post-connect and unknown failures suppress only the exact origin request, so one bad path cannot disable healthy pages. Do not add a private request marker to coordinate the triggers: it would be forwarded to the customer's origin/WAF and could change the representation. The companion repeats cheap request/response gates and may safely shorten a handback's cache lifetime, but it has no body and therefore **never calls Enhancely**, injects, or fetches the origin. Credential, per-request-cache, Set-Cookie-policy, malformed-cache-field, and missing-lifetime vetoes run before config/SSM, so an uncappable response causes no optional I/O. An origin-request-generated response never fires origin-response (AWS-documented). `X-Enhancely-Injected` remains a never-touch-injected-content invariant, not a pairing detector. Every module-deployed function has a fixed 10-second Lambda timeout. The Terraform module reserves 2 seconds for first-invocation SSM config and 2 seconds for cold-start/abort settlement and returning the fail-open response, so `timeout_ms + origin_timeout_ms` may consume at most 6000 ms. Hand-written baked timeout overrides are accepted only when `timeoutMs + originTimeoutMs + ssmTimeoutMs <= 8000`; otherwise all three overrides are ignored together in favor of the safe 800/2000/2000 ms defaults. Everything shared lives in core, `src/shared.ts`, and `src/cache-cap.ts`.
6. **Inject only into `text/html` responses with exact status 200.** This is shared by the core and every production adapter; every other status passes through untouched. `Content-Type` must represent exactly one unambiguous `text/html` value. Adapters with raw field-instance access require exactly one `Content-Type` instance and quote-validate every instance before list aggregation, so top-level commas, duplicate singleton values, or an unbalanced HTTP quoted string veto rewriting. Cloudflare Fetch exposes only folded values; there any comma inside a quoted gate field is conservatively ambiguous and vetoes rewriting, preventing individually malformed instances from healing during folding. HTTP optional whitespace is only SP/HTAB, never Unicode whitespace. `Cache-Control: no-transform` vetoes every production adapter, including an explicit directive separated by malformed whitespace or semicolons. `Content-Disposition` may be absent or explicitly `inline`; `attachment` and every other valid disposition type veto rewriting, and unbalanced quoted strings are treated conservatively. Operator `excludePaths` (TF: `exclude_paths`; CloudFront-style `*` and `?` wildcards, leading `/` optional) are checked before config/API work. Matching decodes RFC 3986 unreserved octets once, treats literal backslashes as `/`, then collapses duplicate slashes and dot-segments; reserved, non-ASCII, malformed, and double-encoded octets remain literal. `X-Robots-Tag: noindex` or `none` vetoes injection even in malformed whitespace-/semicolon-separated input. Body `<meta name="robots">` is not a policy gate; use `excludePaths` for those sections.
7. **`normalizeLite` (4 rules: force https, strip query, strip fragment, strip single trailing slash) is both the cache key AND the URL sent to Enhancely.** It MUST stay byte-for-byte identical to the server's `normalizeUrl` — since the connector sends the normalized URL, a divergence would now serve the wrong record (a correctness bug), not merely a cache miss. Today they are the exact same code; keep them in lockstep. Because this legacy normalization is not idempotent for two or more literal trailing slashes, the strict API boundary additionally requires `normalizeLite(key) === key`; unstable URLs fail open before cache/API work until the whole platform can migrate its normalization atomically.
8. **New adapters must NOT duplicate core logic.** Anything shareable goes into `injector-core`.
9. **Lambda@Edge replacement metadata must be provably safe.** Generated HTML is explicitly UTF-8. The origin-request injector returns the same response it fetched, forwards the origin's headers minus what CloudFront forbids, and removes validators/digests that described the uninjected body. Both the 32 KB header cap and 1 MB combined response cap fail open, with headers counted as UTF-8 bytes.

## Enhancely API contract

- `GET {ENHANCELY_BASE}/api/v1/jsonld/{segment}` — `segment` is the URL-encoded page URL (the connector sends the query-stripped, normalization-stable `normalizeLite(url)`; the server normalizes+hashes it authoritatively).
- `ENHANCELY_BASE` default: `https://app.enhancely.ai`; the official Enhancely API endpoint definitions at `https://docs.enhancely.ai/` list `https://app.enhancely.ai/api/v1/jsonld`.
- Auth required: `Authorization: Bearer <sk-… | sk-org-…>`.
- `Accept: application/ld+json` — the server does an **EXACT string match** on this header. Response body is the raw, already script-safe-escaped JSON-LD string (`<` pre-escaped as a unicode escape). It goes **verbatim** into `<script type="application/ld+json" data-source="Enhancely.ai" data-etag="…">…</script>` — never re-serialize or re-escape it. The two data attributes (Kirby-plugin parity) are debugging surface only: `data-etag` is the record's ETag (weak prefix and quotes stripped, HTML-escaped) so the page source alone reveals which record version a cached copy carries; omitted when no ETag is known. No `data-status` — the connector only injects after a successful lookup.
- `Cache-Control: no-store`, but ETag + `If-None-Match` (304) are supported for cheap revalidation.
- `404` = record missing; `429` = org rate limit (`Retry-After` or `RateLimit-Reset`). Both → fail-open, serve original HTML. For public, non-credentialed requests with an explicit origin cache lifetime, the origin-request injector shortens a generated uninjected response to the next core/config retry and strips origin validators; the companion applies the same capping to eligible responses the injector hands back to CloudFront. Without an explicit `max-age`, `s-maxage`, `Expires`, or `no-cache`, the response stays untouched by default because the connector cannot see (and must not increase) the distribution's DefaultTTL — unless the operator sets `assertedDefaultTtlSeconds` (TF: `asserted_default_ttl_seconds`), an assertion that every associated cache behavior's DefaultTTL is at least that many seconds. Keep it 0 when any associated behavior has DefaultTTL 0. Plain errors create a 10-second URL-local memo. Every high-level `429` also opens the API-key-wide circuit described in rule 4, capped independently at 60 seconds even when a register URL keeps a longer local backoff. `202` = record exists, generation still running → treated as `pending` (negative entry; honors a server `Retry-After` capped at `cacheTtlMs`, else full TTL) — its Problem-JSON body must NEVER be injected. `200` with `X-JsonLd-Status: ignored` or body `{}` = terminal-negative (negative entry for a full TTL, never re-registered). A 429 without `Retry-After` uses `RateLimit-Reset` (delta seconds) as the backoff hint.
- `POST {ENHANCELY_BASE}/api/v1/jsonld { url }` is **register-or-revalidate**, not merely register: with `If-None-Match` it answers `412` (unchanged) and with `Accept: application/ld+json` a known record returns the raw script-safe body + ETag (`200`); unknown URLs are created (`201`, generation enqueued), in-flight ones answer `202`, denylisted/unregistered-hostname `400`, monthly limit `429` + `Retry-After`, plan hard cap `403`. `getJsonLdRegisterLookup` (core) wraps this for high-level `autoRegister` — one direct round-trip, never GET→404→POST — honoring day-scale `Retry-After` (cap 86400 s) as a URL-local backoff for durable 403/429 states. `getJsonLdLookup` is always a read-only conditional GET and never registers. Only a `429` also opens the separately capped 60-second shared circuit; a `403` with `Retry-After` is URL-local only. The cache-cap-only companion never uses the API. Duplicate POSTs are coalesced server-side.
